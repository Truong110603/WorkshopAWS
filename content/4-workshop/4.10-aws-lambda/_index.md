# Building AWS Lambda Statistics

## Objectives

Create a separate AWS Lambda function to process expense statistics from MongoDB Atlas.

---

## 1. Create the Lambda Directory

The project has the following structure:

```text
expense-tracker/

├── backend/
├── frontend/
└── lambda-statistics/
```

Create the Lambda directory:

```text
C:\Codes\expense-tracker\lambda-statistics
```

The Lambda source code is maintained separately from the Backend running on EC2.

---

## 2. Initialize the Lambda Project

Open a terminal and navigate to the Lambda directory:

```bash
cd C:\Codes\expense-tracker\lambda-statistics
```

Initialize the Node.js project:

```bash
npm init -y
```

Install the MongoDB driver:

```bash
npm install mongodb
```

The MongoDB driver allows the Lambda function to connect directly to MongoDB Atlas.

---

## 3. Lambda Project Structure

The Lambda directory contains:

```text
lambda-statistics/

├── index.js
├── package.json
├── package-lock.json
└── node_modules/
```

The main Lambda function is implemented in:

```text
index.js
```

---

## 4. Create the Lambda Function

Create the Lambda function in the AWS Management Console.

![alt text](/WorkshopAWS/images/4-Workshop/4.10/lambdaoverview.png)

Function name:

```text
expense-tracker-statistics
```

Runtime:

```text
Node.js
```

Handler:

```text
index.handler
```

![alt text](/WorkshopAWS/images/4-Workshop/4.10/LambdaFunction.png)

The `index.handler` function is the entry point executed by AWS Lambda.

---

## 5. Environment Variable

The Lambda function uses the MongoDB connection string through an environment variable:

```text
MONGO_URI=<MONGODB_CONNECTION_STRING>
```

The database used by the application is:

```text
expensetracker
```

![alt text](/WorkshopAWS/images/4-Workshop/4.10/lambdaCodeTest.png)

The MongoDB connection string is stored as an environment variable instead of being directly written into the source code.

---

## 6. Processing Workflow

The Lambda function performs the following process:

```text
Lambda
   ↓
MongoDB Atlas
   ↓
Users
   ↓
Expenses
   ↓
Filter by userId
   ↓
Calculate total income / total expenses
   ↓
Calculate balance
   ↓
Save statistics
```

For each user, Lambda retrieves the corresponding expenses, calculates the financial statistics, and stores the result in the `statistics` collection.

---

## 8. Backend Retrieves Lambda Statistics

The Backend provides the following API:

```text
GET http://localhost:3000/api/expenses/lambda-statistics
```

The API retrieves the latest statistics document for the authenticated user from the following MongoDB collection:

```text
statistics
```

The Backend can therefore provide the statistics generated by Lambda to the Frontend.

---

## 9. Result

The statistics processing is separated from the Backend running on EC2.

The system is organized as follows:

```text
EC2
└── Backend API

Lambda
└── Statistics

MongoDB Atlas
├── users
├── expenses
└── statistics
```

AWS Lambda is responsible for processing expense statistics, while the Node.js Backend on EC2 handles the main application APIs.
