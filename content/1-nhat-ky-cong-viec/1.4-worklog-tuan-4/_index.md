## Week 4 Objectives:

* Deep dive into monitoring and auditing services: AWS CloudWatch and CloudTrail.
* Practice monitoring the operational status of EC2 instances and Lambda functions via CloudWatch.
* Learn the concepts of Logs, Metrics, and Alarms in AWS.
* Set up automatic Alarms when resources are overloaded.

## Tasks to be implemented this week:

| Day | Task | Start Date | Completion Date | References |
| --- | --- | --- | --- | --- |
| Monday | Learn about AWS CloudWatch (monitoring) and CloudTrail (activity auditing) | 07/06/2026 | 09/06/2026 | https://cloudjourney.awsstudygroup.com/ |
| Tuesday | Practice configuring Dashboards to monitor EC2 and Lambda using CloudWatch | 09/06/2026 | 10/06/2026 | https://cloudjourney.awsstudygroup.com/ |
| Wednesday | Study Log Groups, Custom Metrics, and CloudWatch Alarms | 11/06/2026 | 11/06/2026 | https://cloudjourney.awsstudygroup.com/ |
| Thursday | Practice creating Alarms and configuring email alerts (SNS) when CPU exceeds 80% | 12/06/2026 | 12/06/2026 | https://cloudjourney.awsstudygroup.com/ |

## Week 4 Results:

* Clearly understood the differences between CloudWatch (performance monitoring) and CloudTrail (security logging/API history).
* Created a Dashboard to visually monitor resources.
* Understood how Logs and Metrics work and set up Alarm thresholds.
* Successfully configured automatic alerts to send emails when the system experiences capacity or performance issues.
